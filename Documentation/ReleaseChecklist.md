# Release checklist

This checklist is required for every tagged release. A release is not ready
because the simulator build is green; the package's hard part is the audio
lifecycle on real hardware. Current repository evidence and unprovable gates
are reconciled in [ReleaseAudit.md](ReleaseAudit.md).

## Early-access releases

An early 0.x release may be published with physical-device cells still unknown,
provided its release notes say so plainly and request privacy-safe bug reports.
It must not be called device-qualified, route-qualified, interruption-qualified,
or endurance-qualified. Required source/API/doc validation and honest known
limitations still apply.

**Evidence reconciliation is currently open.** Historical audit documents and
the checked-in generated inventories do not yet agree on public-symbol and
XCTest totals. Do not cite a test count, pass/skip count, API-symbol count, or
simulator result as current release evidence until the native result bundles,
both API baselines, and generated inventories have been reconciled. See
[First open-source release](FirstOpenSourceRelease.md) and the open Beads work
before selecting a release version.

The historical checks recorded below remain useful as evidence of earlier
work, but are not proof of the current source state. Even a reconciled
simulator/provider-seam run does not prove physical-device or process-crash
behavior.

Local implementation now includes executable transition tests, converter and
Apple-driver fault seams, owner-scoped audio-session leases, canonical
benchmark/coverage artifact upload, DocC tutorials, and the regression ledger.
Remaining evidence includes retained benchmark/coverage artifacts and full
runtime seam execution on Apple hardware.
Hardware-dependent: real routes, interruptions, model/voice catalogs,
energy/thermal/endurance, and process crash/relaunch. Git-host-dependent:
previous-tag comparison, protected branches, reviewed commits, signed tags, and
published release artifacts.

Next evidence commands are maintained in the [open-task acceptance matrix](ReleaseAudit.md#open-task-acceptance-matrix).

## API and package

- [x] Confirm `Package.swift` exposes only the `AppLocalVoice` product.
- [x] Review the public symbol graph for additions, removals, actor-isolation
      changes, and accidental implementation symbols.
- [x] Run `Scripts/validate-public-api.py` against the generated graph and
      review the checked-in [PublicAPISymbols.json](PublicAPISymbols.json)
      baseline.
- [x] Confirm every changed public symbol is represented in
      [PublicAPI.md](PublicAPI.md), the DocC catalog, and the changelog.
- [ ] Once a previous tag exists, compare its generated precise-symbol set with
      the candidate graph using the release procedure in [PublicAPI.md](PublicAPI.md).
- [x] Type-check the clean-client import in CI.
- [x] Confirm the minimum deployment target and Xcode/SDK versions in the
      compatibility contract.

## Reliability evidence

- [x] Run deterministic lifecycle and fault-injection tests.
- [x] Run race, cancellation, stale-callback, repeated-cycle, and bounded
      property/fuzz-case tests with exact test-identity reconciliation; the
      simulator replay is evidence for the simulator only.
- [x] Record deterministic benchmark results for latency, memory, and teardown
      ([Benchmarks.md](Benchmarks.md); device-specific budgets remain open).
- [ ] Complete the physical-device matrix for the supported release devices,
      built-in route, Bluetooth route, wired route, interruptions, and
      foreground/background transitions.
- [ ] Attach reports generated by `Scripts/run-device-validation.sh` for every
      physical device used in the release matrix.
- [ ] Verify model installation and enhanced voice availability on at least one
      clean device.
- [x] Run the deterministic privacy validator over portable evidence and the
      crash-report schema validator in CI.
- [ ] Confirm no microphone, transcript, speech text, or credentials appear in
      retained physical-device logs or crash attachments; no physical
      attachment has been validated in this checkout.

## Documentation and distribution

- [x] Build DocC with warnings as errors.
- [x] Update migration notes for any behavior or compatibility change.
- [x] Update `CHANGELOG.md` with known limitations and unknown device cells.
- [x] Confirm the license, security policy, code of conduct, and contribution
      workflow are current.
- [x] Confirm the published Git host has real CODEOWNERS ownership and private
      vulnerability reporting enabled.
- [ ] Tag the release from a clean, reviewed commit and publish checksums or
      release artifacts according to the repository's distribution policy
      after the hosted release-validation workflow passes.
